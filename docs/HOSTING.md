# Hosting Clearline

Two ways to host it. Pick by what you want to show.

| | **A. Lite edition on a free web host** | **B. Full edition on a VM** |
|---|---|---|
| What runs | One container: the whole app, dashboard and self-driving simulator | App + reporting + Kafka + Postgres + ClickHouse + Redis + Jaeger + Prometheus + Grafana |
| Needs | A GitHub account and a Render account (free) | A VM with about 4 cores and 8 GB RAM (an Oracle Cloud "Always Free" ARM VM has fit this; check its current terms and availability), or a few months of student cloud credits |
| Good for | A link on your resume that is always one click away | Interviews where you want to show Kafka, ClickHouse, Reports and tracing |
| Cost | Free | Free on a free-tier VM, otherwise roughly $10-50 a month (check current prices) |

Both steps need your own accounts and credentials, which an assistant cannot create or enter for you. **The Render path has not been tested end to end**, so treat the first deploy as a dry run and see the troubleshooting table if it fails.

## A. Lite edition on Render (free)

### 1. Put the code on GitHub
With the GitHub CLI (`gh`), signed in (`gh auth status` should show your account), from the project folder:

```bash
git branch -M main
gh repo create clearline --private --source=. --remote=origin --push
git push origin --tags
```

`--private` keeps it to you (change it later with `gh repo edit --visibility public --accept-visibility-change-consequences`). Without the CLI:
create an empty repository on github.com, then `git remote add origin https://github.com/<you>/clearline.git`, `git branch -M main`, `git push -u origin main`, `git push origin --tags`.

Notes:
- Only development default passwords (`admin123` and similar) are committed; real ones are generated by Render (step 3).
- Commits carry your name and the email set in `git config`. Check `git log -3 --format='%an <%ae>'` first if you do not want an address public.
- `clearline-lite/` is a frozen reference copy and is not used by the deploy; the root `Dockerfile` builds the dashboard and app from source.
- If `git push` asks for a password, use `gh auth login` rather than your account password.

### 2. Create the service from the blueprint
1. Sign in at render.com (check their pricing page for whether the free web-service tier needs a payment method today).
2. **New +** > **Blueprint** > connect GitHub > pick the `clearline` repository. For a private repo, grant Render access to it when prompted.
3. Render reads [`render.yaml`](../render.yaml) and shows one web service called `adexchange` on the **Free** plan. Click **Apply**.
4. The first build takes several minutes: it installs dashboard dependencies, builds the React app, builds the Java app, then starts it.

**Render CLI (optional).** Install it from Render's official documentation, run `render login` (it opens a browser for you to approve), then use it to watch logs and trigger deploys (`render --help` lists the commands in your version). The Blueprint step above is done in the dashboard, which is the path this guide verifies.

### 3. Get your admin password
`render.yaml` asks Render to generate `ADMIN_PASSWORD`, `ADVERTISER_PASSWORD`, `JWT_SECRET` and `HMAC_SECRET`. Open the service > **Environment** tab to read them. Sign in at `https://adexchange-xxxx.onrender.com` as `admin` with `ADMIN_PASSWORD`, or as `advertiser1` to `advertiser8` with `ADVERTISER_PASSWORD`.

### 4. Check that it works
- The URL shows the splash screen, then the login.
- **Performance** shows spend moving (the built-in simulator runs at about 120 requests per second).
- **Live auction** shows ads changing in the slots, with a bid ladder beside them.
- `https://<your-service>/actuator/health` returns `{"status":"UP"}`.

### Free-tier behaviour to know about
- **It sleeps when idle** (about 15 minutes without traffic on Render's free web services) and takes up to a minute or two to wake. Open the link a minute before showing it. The simulator resumes by itself.
- **512 MB RAM.** `render.yaml` sizes the heap (320 MB), uses the serial GC and a low simulator rate for that. If it restarts with out-of-memory in the logs, lower `AUTOSTART_SIM_RATE` (for example to 60) in the Environment tab.
- **State resets on every restart.** Lite mode keeps campaigns in memory and re-seeds the demo set, so campaigns created by hand disappear when it sleeps.
- **Plan terms change.** Check Render's current free-tier limits.

### Troubleshooting
| Symptom | Likely cause and fix |
|---|---|
| Build fails or times out | The Docker build (npm + Maven) is heavy for a small builder. Build the image locally and deploy that: `docker build -t <you>/clearline:1 .`, `docker push <you>/clearline:1`, then create a **Web Service** from an **existing image** with the environment variables from `render.yaml`. |
| Service starts then restarts | Out of memory: lower `AUTOSTART_SIM_RATE`, and read the log for the real error. |
| Login fails | You used the development password. Use the generated `ADMIN_PASSWORD`. |
| 502 right after deploy | The JVM is still starting (20-40 s on a small instance). Wait and refresh. |
| Live auction page is empty | The simulator is not running. Open **Simulator** and press Start, or check `AUTOSTART_SIM_RATE`. |

### Other free hosts
The same `Dockerfile` runs anywhere that runs a container (Koyeb, Fly.io, Cloud Run and similar). Set `PORT` if the host does not, keep the `JAVA_OPTS` heap small, and copy the environment variables from `render.yaml`. Free tiers change often; check them first.

## B. Full edition on a VM

1. Create an Ubuntu 22.04 or 24.04 VM with at least 4 cores and 8 GB RAM. Open only what you need: 22 (SSH) and 80/443 if you use a reverse proxy. **Never expose Kafka, Postgres, ClickHouse or Redis to the internet.**
2. Install Docker: `curl -fsSL https://get.docker.com | sh`, then log out and back in.
3. Get the code and start it:

```bash
git clone https://github.com/<you>/clearline.git && cd clearline
export ADMIN_PASSWORD='choose-a-long-password' ADVERTISER_PASSWORD='choose-another' \
       JWT_SECRET="$(openssl rand -hex 32)" HMAC_SECRET="$(openssl rand -hex 32)" \
       POSTGRES_PASSWORD="$(openssl rand -hex 16)" CLICKHOUSE_PASSWORD="$(openssl rand -hex 16)"
docker compose -f deploy/compose.full.yml up -d --build
```

4. After a few minutes, `docker compose -f deploy/compose.full.yml ps` should show every service running (healthy where a health check exists).
5. The app listens on port 8080. For HTTPS with a domain, put Caddy in front: a two-line `Caddyfile` (`your.domain { reverse_proxy localhost:8080 }`) gets certificates automatically.
6. Jaeger (16686), Grafana (3000) and Prometheus (9090) are published by the compose file: keep them behind the firewall or an SSH tunnel (`ssh -L 16686:localhost:16686 you@vm`).

The compose file falls back to development database passwords unless you export the variables above; always set them on a VM with a public address. To stop and delete everything, data included: `docker compose -f deploy/compose.full.yml down -v`.
